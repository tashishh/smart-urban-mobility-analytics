SECTION 1 — SYSTEM ARCHITECTURE OVERVIEW
==================================================

How the full stack works together:

DATABASE (MySQL)
  └── Stores all 601,662 cleaned trip records in the `trips` table
  └── Has 5 reusable views: hourly_summary, weekday_summary,
      distance_summary, vendor_summary, weekend_summary

BACKEND (Flask — Python)
  └── Connects to MySQL database
  └── Exposes API endpoints that query the views
  └── Returns the results as JSON
  └── Does NOT do heavy data processing — the SQL views handle that

API (JSON responses)
  └── Acts as the bridge between the database and the frontend
  └── Each endpoint answers one specific business question
  └── Frontend fetches these URLs to get the data it needs

FRONTEND (HTML + CSS + JavaScript + Chart.js)
  └── Runs in the browser
  └── Calls the API endpoints using JavaScript fetch()
  └── Takes the JSON response and displays it as cards and charts
  └── Never talks to the database directly

FLOW SUMMARY:
  Browser → fetch(API URL) → Flask endpoint → MySQL view → JSON → Chart.js

----------------------------------------------
ENDPOINT 1: /api/kpis
----------------------------------------------
Purpose  : Return high-level summary numbers for the KPI cards
           at the top of the dashboard
Method   : GET
SQL Used : Direct COUNT and AVG on the trips table (no view needed)

SQL Query:
  SELECT
      COUNT(*)                        AS total_trips,
      ROUND(AVG(trip_distance_km), 2) AS avg_distance_km,
      ROUND(AVG(passenger_count), 2)  AS avg_passengers,
      COUNT(DISTINCT vendor_id)       AS total_vendors
  FROM trips;

JSON Response Shape:
  {
    "total_trips": 601662,
    "avg_distance_km": 3.42,
    "avg_passengers": 1.51,
    "total_vendors": 2
  }

Dashboard Use:
  4 KPI cards at the top of the page
  - Total Trips
  - Average Distance
  - Average Passengers
  - Number of Vendors

SECTION 4 — FLASK FILE PLAN
==================================================

backend/
├── app.py          # Main Flask app — all routes defined here
├── db.py           # Database connection function (reusable)
└── requirements.txt  # Flask and mysql-connector-python

app.py structure:
  - Import Flask, db connection
  - Define each route with @app.route
  - Each route calls db, runs SELECT on view, returns jsonify()

db.py structure:
  - One function: get_connection()
  - Returns a live MySQL connection using mysql-connector-python
  - Reads host, user, password, database from config or hardcoded for now

SECTION 5 — WHAT THE FRONTEND NEEDS
==================================================

The frontend dashboard will have:

  1. KPI Cards row (top of page)
     - Total Trips        ← /api/kpis → total_trips
     - Avg Distance       ← /api/kpis → avg_distance_km
     - Avg Passengers     ← /api/kpis → avg_passengers
     - Weekend Group %    ← /api/weekend-summary → group_trip_pct

  2. Line Chart — Hourly Demand
     ← /api/hourly-summary → hour_of_day + total_trips

  3. Bar Chart — Daily Demand
     ← /api/weekday-summary → day_of_week + total_trips

  4. Bar Chart — Distance Buckets
     ← /api/distance-summary → distance_bucket + total_trips

  5. Vendor Comparison Table
     ← /api/vendor-summary → vendor_id + total_trips + avg_distance_km

  6. Weekday vs Weekend Summary Card
     ← /api/weekend-summary → day_type + total_trips + group_trip_pct
